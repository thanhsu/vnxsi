# VNX v0.1 — Design Spec

- **Ngày:** 2026-10-02
- **Trạng thái:** **Superseded** (2026-10-03) bởi [Marketplace Wave 1 spec](2026-10-03-vnxsi-marketplace-wave1-design.md). Dự án đã pivot sang marketplace.
- **Phạm vi:** Landing v2 (`apps/web`) + VNX API v0.1 (`apps/api`)

## 1. Định vị

**VNX — AI that works, not just chats.**

Đưa cho VNX một goal. VNX lập plan, dừng lại xin duyệt, thực thi bằng tool, tự kiểm chứng, rồi trả kết quả, với mọi bước được ghi lại (model, token, cost, thời gian).

VNX là **execution/orchestration layer** nằm trên các AI model và tool. Không phải chatbot, không phải model, không phải IDE.

**Quyết định:**

- vnx.si **bỏ hoàn toàn** concept "Vietnam AI Index" (bảng xếp hạng, benchmark, marketplace Việt).
- Đối tượng Phase 1: developer / technical user.
- VNX **tự viết** agent loop (không bọc Claude Code/Codex) để nắm được từng step, cost, policy và đa model.
- Dogfood đầu tiên: **project cá nhân**, cụ thể là chính repo `vnxsi`. Không dùng code công ty.
- Jira **không bắt buộc**. Core không phụ thuộc Jira/GitHub/GitLab; các tích hợp đó sau này cắm vào qua MCP như plugin tùy chọn.

## 3. Phần 1 — Landing v2 (`apps/web`)

### 3.1 Giữ nguyên

Cloudflare Worker + static assets + D1 + `/api/waitlist` + Turnstile tùy chọn + honeypot. Không có build step.

### 3.2 Song ngữ EN/VI

- Một `public/index.html`. Mọi chuỗi hiển thị gắn `data-i18n="key"` (hoặc `data-i18n-html`, `data-i18n-attr`). Bản EN nằm sẵn trong markup và được đọc lại khi trang tải; bản VI nằm trong object JS `VI` ngay trong trang.
- Chọn ngôn ngữ theo thứ tự: `?lang=en|vi` → `localStorage("vnx.lang")` (bọc try/catch) → `navigator.language` bắt đầu bằng `vi` → mặc định `en`.
- Nút chuyển EN/VI ở header; khi đổi thì cập nhật `<html lang>`, `document.title`, meta description.
- Markup mặc định trong HTML là bản EN (để crawler và trường hợp không có JS vẫn đọc được).
- Thông báo lỗi trả về từ API theo `lang` gửi kèm (mặc định EN).

### 3.3 Các section

Nội dung trung thực: không bịa số user, logo khách hàng, testimonial hay benchmark.

1. **Header:** logo VNX, anchor tới các section, toggle EN/VI, CTA "Join early access".
2. **Hero:** tagline + một câu mô tả + mockup tĩnh một task đang chạy: goal, danh sách step (✓ xong, ● đang chạy, ○ chờ), một step chờ duyệt với nút *Approve / Reject / Edit*.
3. **Problem:** vòng copy-paste ChatGPT → Claude → Git → Browser → Excel, so với VNX: Goal → Result.
4. **How it works:** Goal → Plan → Approve → Execute → Verify → Result.
5. **Human in control:** bảng permission level (READ, WRITE, EXECUTE, EXTERNAL_ACTION, DESTRUCTIVE) và ví dụ policy (`filesystem.read` AUTO, `filesystem.write` APPROVAL, `database.drop` BLOCK).
6. **Observable by default:** mockup timeline (thời gian, tool/model, token, cost) + tổng cost của task.
7. **Model router:** Auto / Cheap / Balanced / Best / Local only, ghi rõ "coming".
8. **Agents:** Developer Agent (đầu tiên); Code Reviewer, Research, Content gắn nhãn "later".
9. **Roadmap:** v0.1 Developer Agent → Multi-model → Memory + RAG → Automation (schedule/trigger/webhook).
10. **Waitlist form** (mục 3.4).
11. **Footer:** © VNX, liên hệ, chính sách dữ liệu ngắn (giữ ý consent hiện có).

Thiết kế: dark-first, có light mode, kiểu developer tool (mono font cho mockup terminal/timeline), responsive tới 360px, đạt tương phản WCAG AA, `prefers-reduced-motion` tắt animation.

### 3.4 Waitlist

- **Personas** (chọn nhiều, ≥1): `developer | tech-lead | devops | ai-builder | other`.
- **message** (tùy chọn, ≤1000 ký tự): "Bạn muốn giao việc gì cho agent?" / "What would you hand off to an agent?"
- **spendBand** (tùy chọn, chi tiêu AI/tháng, USD): `none | lt20 | 20-100 | 100-500 | gt500`.
- **lang:** `en | vi`, lấy từ ngôn ngữ đang hiển thị; giá trị khác sẽ quy về `en`.
- **consent** bắt buộc; honeypot `website`; Turnstile nếu có secret (giữ nguyên).
- **Migration `0002_waitlist_lang.sql`:** `ALTER TABLE waitlist ADD COLUMN lang TEXT;`. Không có CHECK constraint nên các bản ghi cũ (persona/spend band kiểu cũ) giữ nguyên.
- `saveEntry` ghi `lang`; khi upsert thì cập nhật `lang`.
- Cập nhật `test/waitlist.test.ts` theo personas/spend bands mới, có test cho `lang` và cho lỗi trả về theo ngôn ngữ.

## 4. Phần 2 — VNX API v0.1 (`apps/api`)

### 4.1 Môi trường

- Chỉ chạy **local** (Docker Compose trên máy dev). Không public ra internet ở v0.1, vì agent chạy được shell.
- Python 3.13, `uv`, FastAPI, Uvicorn, SQLAlchemy 2 (async) + asyncpg, Alembic, Pydantic v2, `sse-starlette`, `anthropic` SDK, pytest + pytest-asyncio + httpx.
- Postgres 16 dùng image `pgvector/pgvector:pg16` (chưa dùng vector ở v0.1).
- Auth: header `Authorization: Bearer <VNX_API_TOKEN>` (token từ env). Một user.
- Cấu hình qua env: `DATABASE_URL`, `VNX_API_TOKEN`, `ANTHROPIC_API_KEY`, `VNX_WORKSPACES_ROOT`, `VNX_DEFAULT_MODEL` (mặc định `claude-sonnet-5-5`).

### 4.2 Cấu trúc thư mục

```
apps/api/
  pyproject.toml
  Dockerfile
  docker-compose.yml        # api + postgres
  alembic/                  # migrations
  src/vnx/
    main.py                 # FastAPI app, routers
    config.py
    db.py                   # engine, session
    models.py               # SQLAlchemy tables
    schemas.py              # Pydantic I/O
    api/tasks.py            # REST + SSE
    runtime/
      state.py              # TaskStatus + transition rules
      runner.py             # vòng lặp plan → approve → execute → verify
      planner.py            # Planner protocol + ScriptedPlanner + LLMPlanner
      events.py             # in-process event bus cho SSE
    policy.py               # PolicyEngine
    tools/
      base.py               # Tool protocol, Permission, ToolResult
      registry.py
      filesystem.py         # read/write/list trong workspace
      git.py                # status/diff/branch/commit
      shell.py              # allowlist
    models_providers/
      base.py               # ModelProvider protocol, ModelResponse(usage, cost)
      anthropic.py
      pricing.py            # bảng giá → cost USD
  tests/
```

### 4.3 State machine của Task

```
CREATED → PLANNING → WAITING_APPROVAL → EXECUTING → VERIFYING → COMPLETED
                         │    ▲               │
                         │    └── (step cần APPROVAL) ──┘
                         └── reject → CANCELLED
Bất kỳ trạng thái chưa kết thúc → FAILED | CANCELLED
EXECUTING ↔ PAUSED
```

- Các chuyển trạng thái hợp lệ được định nghĩa tập trung trong `runtime/state.py`; chuyển sai sẽ raise `InvalidTransition`, API trả `409`.
- Trạng thái kết thúc: COMPLETED, FAILED, CANCELLED.

### 4.4 Tool và Policy

```python
class Permission(StrEnum): READ, WRITE, EXECUTE, EXTERNAL_ACTION, DESTRUCTIVE
class Decision(StrEnum):   AUTO, APPROVAL, BLOCK

class Tool(Protocol):
    name: str                 # "filesystem.read"
    description: str
    input_schema: dict        # JSON Schema, đưa thẳng cho model
    permission: Permission
    async def execute(self, args: dict, ctx: ToolContext) -> ToolResult: ...
```

Policy mặc định: READ → AUTO, WRITE → APPROVAL, EXECUTE → APPROVAL (trừ lệnh shell trong allowlist → AUTO), EXTERNAL_ACTION → APPROVAL, DESTRUCTIVE → BLOCK. Từng project có thể override theo tên tool, nhưng không được hạ DESTRUCTIVE xuống AUTO.

Tool ở v0.1:

| Tool | Permission | Ghi chú |
|---|---|---|
| `filesystem.read`, `filesystem.list` | READ | Chỉ trong workspace của project |
| `filesystem.write` | WRITE | Như trên |
| `git.status`, `git.diff` | READ | |
| `git.branch`, `git.commit` | WRITE | Không có `push` ở v0.1 |
| `shell.execute` | EXECUTE | Allowlist theo project (vd `npm test`, `uv run pytest`); lệnh ngoài allowlist → APPROVAL |

**Sandbox:** mọi path được resolve và phải nằm trong `VNX_WORKSPACES_ROOT/<project>`; symlink thoát ra ngoài bị chặn. Shell chạy với `cwd` = workspace, timeout mặc định 120s, output cắt ở 64 KB, env đã lọc bỏ secret (`*_KEY`, `*_TOKEN`, `*_SECRET`).

### 4.5 Model provider

```python
class ModelProvider(Protocol):
    async def complete(self, *, model: str, system: str, messages: list,
                       tools: list[dict]) -> ModelResponse: ...
# ModelResponse: content, tool_calls, input_tokens, output_tokens, cost_usd
```

v0.1 chỉ cài `AnthropicProvider`. Cost tính từ bảng giá trong `pricing.py`. Nếu model không có trong bảng thì `cost_usd = null` và ghi cảnh báo, chứ không đoán giá.

### 4.6 Runner (vòng lặp agent)

1. **PLANNING:** Planner nhận goal + context project (cây thư mục, README) → trả về plan là danh sách step `{title, intent}`. Lưu thành các `task_steps` ở trạng thái `PENDING`.
2. **WAITING_APPROVAL (plan):** luôn dừng để người dùng duyệt plan. `approve` → EXECUTING; `reject` → CANCELLED; `edit` → thay plan bằng bản người dùng gửi rồi chạy tiếp.
3. **EXECUTING:** với từng step, chạy tool-use loop với model (giới hạn `max_turns` mỗi step, mặc định 20). Mỗi lần gọi model hoặc tool sinh một bản ghi (`model_runs` / `tool_executions`) gắn với step. Trước mỗi lần gọi tool thì hỏi PolicyEngine:
   - AUTO → chạy.
   - APPROVAL → tạo `approvals` (pending), task chuyển WAITING_APPROVAL, runner dừng. Khi được duyệt thì chạy tiếp từ đúng lần gọi tool đó.
   - BLOCK → trả lỗi cho model (`blocked by policy`), ghi audit, model tự đổi hướng.
4. **VERIFYING:** chạy các lệnh verify của project (vd `npm test`), sau đó model tóm tắt kết quả + `git diff`.
5. **COMPLETED** với `result` = tóm tắt + diff; hoặc **FAILED** kèm lý do.

Runner chạy dạng background task (`asyncio`) trong process API. Mọi trạng thái được lưu trong DB, nên khi khởi động lại, task đang EXECUTING được đánh dấu PAUSED để người dùng chủ động `resume`.

**`ScriptedPlanner` / `ScriptedProvider`:** bản giả có kịch bản định sẵn, dùng cho test và plan 1 (chưa cần API key).

### 4.7 Dữ liệu

| Bảng | Cột chính |
|---|---|
| `projects` | id, slug, name, workspace_path, policy_overrides (jsonb), shell_allowlist (jsonb), verify_commands (jsonb), created_at |
| `tasks` | id, project_id, goal, status, model, result (jsonb), error, total_cost_usd, created_at, updated_at |
| `task_steps` | id, task_id, step_number, title, intent, status, started_at, finished_at |
| `model_runs` | id, task_id, step_id, model, input_tokens, output_tokens, cost_usd, duration_ms, request (jsonb), response (jsonb), created_at |
| `tool_executions` | id, task_id, step_id, tool, args (jsonb), decision, status, output (jsonb), duration_ms, created_at |
| `approvals` | id, task_id, kind (`plan`/`tool`), tool_execution_id, status (`pending`/`approved`/`rejected`), payload (jsonb), decided_at |
| `audit_logs` | id, task_id, actor, action, detail (jsonb), created_at |

ID dùng UUIDv7 (sắp xếp được theo thời gian). Timeline của một task = gộp `model_runs`, `tool_executions`, `approvals` theo `created_at`.

### 4.8 API

| Method | Path | Mô tả |
|---|---|---|
| POST | `/api/v1/projects` | Tạo project (slug, workspace_path phải nằm trong root) |
| GET | `/api/v1/projects` | Danh sách project |
| POST | `/api/v1/tasks` | `{project, goal, model?}` → `{taskId, status: "PLANNING"}` |
| GET | `/api/v1/tasks/{id}` | Task + steps + approval đang chờ + tổng cost |
| GET | `/api/v1/tasks/{id}/timeline` | Danh sách sự kiện đã sắp xếp |
| GET | `/api/v1/tasks/{id}/events` | SSE: `status`, `step`, `model_run`, `tool_execution`, `approval_required`, `done` |
| POST | `/api/v1/tasks/{id}/approve` | `{approvalId, editedPlan?}` |
| POST | `/api/v1/tasks/{id}/reject` | `{approvalId, reason?}` |
| POST | `/api/v1/tasks/{id}/cancel` / `resume` | |
| GET | `/api/v1/health` | Không cần auth |

Lỗi trả về theo định dạng thống nhất `{error: {code, message}}`: 401 thiếu hoặc sai token, 404, 409 khi chuyển trạng thái sai, 422 khi validate thất bại.

### 4.9 Kiểm thử

- **Unit:** state transitions; PolicyEngine (bao gồm việc không cho override DESTRUCTIVE); sandbox path (`..`, symlink, absolute path); allowlist của shell; tính cost.
- **Integration** (Postgres thật qua Compose hoặc testcontainers): luồng đầy đủ với `ScriptedPlanner` + `ScriptedProvider` (tạo task → plan → approve → tool WRITE cần approval → approve → verify → COMPLETED), reject plan → CANCELLED, tool BLOCK.
- **Không** gọi API Anthropic thật trong test tự động. Có một smoke test thủ công, đánh dấu `@pytest.mark.live`.

## 5. Tiêu chí thành công v0.1

Trên repo `vnxsi` (mount làm workspace), giao goal: *"Add per-IP rate limiting (5 requests/minute) to `/api/waitlist` and cover it with tests"* (việc thêm cột `lang` đã làm ở plan 1, nên chọn goal khác). VNX phải:

1. Sinh plan và dừng chờ duyệt.
2. Đọc code, sửa file (có xin duyệt lần ghi), chạy `npm test`.
3. Trả về tóm tắt + `git diff` với test pass.
4. Timeline hiển thị mọi lần gọi model/tool, kèm token, cost và thời gian; tổng cost khớp tổng các `model_runs`.

Toàn bộ không cần copy-paste giữa các tool.

## 6. Thứ tự triển khai (mỗi mục là một implementation plan riêng)

1. **Landing v2:** i18n, nội dung mới, thay đổi waitlist + migration 0002 + test.
2. **API scaffold:** Compose, schema + Alembic, state machine, PolicyEngine, tool sandbox (filesystem/git/shell), REST + SSE, runner chạy với Scripted planner/provider, toàn bộ test ở mục 4.9.
3. **Claude thật:** `AnthropicProvider`, `LLMPlanner`, pricing, smoke test live, trang debug tối giản để xem timeline.
4. **Dogfood:** chạy tiêu chí ở mục 5, ghi lại các điểm hỏng → backlog.

## 7. Ngoài phạm vi v0.1

MCP, Jira/GitHub/GitLab, `git.push`, multi-model router, memory/RAG/embedding, dashboard Next.js, nhiều user/organization, billing, marketplace, deploy API ra public.
